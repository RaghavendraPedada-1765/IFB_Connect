# Review fixes — 14 October 2026

Changes made after the full project review. Server changes were compiled and the isolated suite run (57 checks, plus the 500-client load check) in a Linux container; the WinUI client and PowerShell scripts could not be built or run there and need a Windows build and the manual checks below.

## Source control and packaging
- `.gitignore` no longer contains `**/data/`. Git on Windows ignores case, so it was hiding `src/IFB.Server/Data` (DbContext, bootstrap and both migration sets) from the repository. Runtime attachments are ignored via `**/storage/` and `src/IFB.Server/Data/files/`.
- `Export-Developer-Handoff.ps1` no longer blocks folders named `data` (same case problem); it blocks only `src/IFB.Server/Data/files` and fails if the DbContext or migrations are missing from the package.
- Attachments now default to `storage/files` instead of `data/files`, which resolved into the source folder on Windows. Existing attachments keep working because their stored paths are unchanged. Date folders no longer depend on the culture's date separator.

## Security
- `POST auth/logout` accepts the refresh token without an access token. Before, the client sent it unauthenticated, got 401 and the token stayed valid on the server.
- Employees can no longer rename themselves or change their department (`PATCH users/me/profile` now allows only the job title). Administrators edit display names in Administration → Edit user; profile-only edits no longer end that user's sessions.
- Local usernames are validated the same way sign-in normalises them; lengths are enforced (SQLite ignores column lengths).
- `Install-Server.ps1` runs the service as `NT SERVICE\IFBConnectServer` (or `-ServiceAccount`), removes ordinary users' access to the installation folder (JWT key, certificate password, database), gives the service write access only to `database`, `storage` and `logs`, and grants it read access to the certificate file.
- `auth/refresh` has its own per-address rate limit (`RateLimiting:RefreshPerMinute`, default 30).

## Reliability
- Background workers catch and log failures; a worker error no longer stops the server (`BackgroundServiceExceptionBehavior.Ignore` plus per-loop handling). Retention runs two minutes after start, then every interval, so daily restarts no longer prevent it. Locked attachment files no longer abort a retention run.
- The client reconnects at the configured interval and then every 30 seconds indefinitely instead of giving up after about 40 seconds.

## Performance
- Read receipts are "read through": one hub or REST call marks the given message and all earlier incoming messages read and broadcasts one event. The client sends one call for the newest visible message instead of one per message, and marks all of your messages up to the receipt as read.
- Loading history no longer marks messages read or broadcasts receipts (it previously did both, one event per message).
- History queries use split queries for reactions and receipts.
- Typing notifications are sent at most every 2.5 seconds instead of on every keystroke.
- Audit records only state-changing calls, administration and file downloads; `Retention:AuditDays` (default 365) prunes old entries.

## Correctness
- Typing indicators and live announcements show the display name rather than the username.
- Deleting a message removes its attachment (file and record) unless another live message uses it.
- REST edits are sanitised like hub edits; reactions on deleted messages are rejected over the hub as well as REST; `GET files/{id}/info` rejects attachments without a conversation; announcements reject past expiry times.
- Unused repository registrations were removed from `Program.cs`; duplicated certificate-loading branch removed.
